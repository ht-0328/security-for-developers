学び方：何から、どう学ぶか
実務で使えるようになるまでの道順と、本サイトの使い方

セキュリティは範囲が広く、「全部」を学ぼうとすると最初の一歩で止まります。開発者に必要なのは、自分が作るものに入り込む穴の種類を知り、穴を作らない書き方を体で覚え、部品と設定を最新に保ち、何かあったとき動けることです。このページでは、その順番と教材、本サイトの使い方を説明します。

🧭このページで理解してほしいこと
  • 「実務で使える」とは3つのこと：レビューで気づける・設計で先回りできる・ニュースの影響を判断できる
    • 気づける：文字列をつないだ SQL、ID を変えれば他人のデータが見える API を、レビューで指摘できる
    • 先回りできる：設計のときに「誰が・何に・何をしてよいか」「悪用されたらどうなるか」を1回考えられる
    • 判断できる：「〇〇に脆弱性」のニュースを見て、自分のシステムが影響を受けるか、今日直すかを決められる
    • 攻撃ツールの操作や暗号理論は、開発者の仕事には要らない
  • 開発者の守備範囲は4つ：コード・部品・設定・運用
    • コード：自分が書く処理の穴（第3〜5章）
    • 部品：使っているライブラリ・フレームワーク・OS の穴（第6章）
    • 設定：公開範囲・権限・初期設定のミス（第7章）
    • 運用：ログ・監視・更新・事故対応（第8章）
    • 人を狙う攻撃（フィッシングなど）は組織全体の課題。開発者は「人が間違えても被害が広がらない作り」で貢献する
  • 学ぶ順番は6段階：地図 → 10のルール → 手を動かして体験 → 部品と設定 → 開発の流れに組み込む → 続ける
    1. 地図（第1章）：守るもの・言葉の関係・ニュースの読み方。半日
    2. 10のルール（第2章）とチェックリスト：明日からの行動。1日
    3. 体験（第3〜5章＋練習教材）：Web の穴を自分で突いて、自分でふさぐ。2〜4週間
    4. 部品と設定（第6〜8章）：依存スキャンを自分の CI に入れる。1〜2週間
    5. 開発の流れ（第9章）：PR テンプレートにチェック項目を入れる。1週間
    6. 続ける：脆弱性情報を受け取り、年1回 IPA 10大脅威と OWASP Top 10 を読み直す
  • 教材は「日本語・無料・手を動かせる」を優先する
    • 日本語の正解集：IPA「安全なウェブサイトの作り方」（無料 PDF）
    • 手を動かす：PortSwigger Web Security Academy（無料・英語・ブラウザだけ）、OWASP Juice Shop
    • 体系的な1冊：徳丸本（『体系的に学ぶ 安全なWebアプリケーションの作り方』）
    • 実装の正解集：OWASP Cheat Sheet Series
  • 練習は自分のものか、練習用に用意された環境だけ：他人のシステムに試すのは犯罪（不正アクセス禁止法）
  • 本サイトは「読んだら閉じて思い出す」で使う：章末の想起練習 → 学習記録 → 1日後・3日後・7日後に復習

読み終えたら、本文を見ずに各項目を自分の言葉で説明できるか確かめてください。

1. 「実務で使える」とは何か：3つのできること

セキュリティの専門家になる必要はありません。開発者として「使える」状態は、次の3つができることです。学び始める前に、この3つを到達点として置いてください。

できること 1レビューで気づける

文字列をつないで作った SQL、画面側だけの入力チェック、URL の ID を変えれば他人のデータが見える API。こうした「よくある穴」を、コードを見た瞬間に指摘できる。

できること 2設計で先回りできる

新しい機能を作るとき、「誰が・何に・何をしてよいか」「この機能が悪用されたら何が起きるか」を1回考え、設計に書き残せる。

できること 3ニュースの影響を判断できる

「〇〇に深刻な脆弱性」の記事を見て、自分のシステムがその部品を使っているか、外から届くか、今日直すべきかを判断できる。

💡イメージで理解する

家を建てる大工に置き換えると、必要なのは「泥棒の手口を全部知ること」ではなく、鍵のかかる窓を選び、鍵をかけ忘れない設計にし、欠陥が見つかった建材を交換できることです。防犯の専門家（警備会社）とは役割が違います。

3. 学ぶ順番（ロードマップ）

順番が大切です。攻撃手法の暗記から入ると、知識が増えても自分のコードにどう効くかが見えません。地図 → 行動のルール → 手を動かして体験 → 自分のプロジェクトに適用 → 続けるの順で進めます。

STEP 1 ／ 半日地図を持つ（第1章）

守るもの3つ、脆弱性・脅威・リスクの関係、CVE・CVSS などニュースの用語。「わからない言葉がない」状態にする。

STEP 2 ／ 1日10のルールとチェックリスト（第2章）

明日からの行動を決める。自分の今のプロジェクトにチェックリストを当て、×が付いた項目を書き出す。

STEP 3 ／ 2〜4週間Web の穴を体験する（第3〜5章）

本文の危険なコードと安全なコードを読み、練習教材で実際に攻撃が成立する様子と、直せば止まる様子を自分の手で確かめる。

STEP 4 ／ 1〜2週間部品・設定・運用（第6〜8章）

自分のリポジトリに依存スキャンと自動更新を入れる。セキュリティヘッダーと公開範囲を確認する。事故の初動手順を1枚にする。

STEP 5 ／ 1週間開発の流れに組み込む（第9章）

PR テンプレートにチェック項目を入れ、CI に自動検査を足す。設計レビューに「悪用されたら」の1問を加える。

STEP 6 ／ ずっと続ける

使っている部品の脆弱性情報を受け取る。毎年1月の IPA 10大脅威と、改訂時の OWASP Top 10 を読み直す。

5. やってはいけない学び方

⚖️他人のシステムで試さない

本サイトで学ぶ攻撃の仕組みを、自分の管理下にないサイトやサービスに対して試すことは、不正アクセス禁止法などに触れる犯罪です。「ID を変えてみただけ」「診断のつもりだった」は通りません。練習は、自分で立てた環境（Juice Shop など）か、練習用として公開されている教材（Web Security Academy のラボ）だけで行ってください。勤務先のシステムであっても、許可なく診断してはいけません。

陥りやすい学び方なぜ効かないか代わりに
攻撃手法の名前を片っ端から覚える自分のコードのどこに効くかが見えず、使えない知識になる「何が起きる → なぜ → どう防ぐ → どう確かめる」の順で、1つずつ自分のコードに当てる
ツールを入れて安心するツールは「よくある穴」の一部しか見つけない。認可の不備はほぼ見つけられないツールは第9章の位置づけで使い、認可・設計は人が見る
暗号理論から入る開発者が暗号を自作することはない。使い方の正解を知れば足りる第5章の「ライブラリと推奨アルゴリズム」だけ押さえる
一度読んで終わりにする読んだ直後は分かった気になるが、1週間後のレビューで思い出せない章末の想起練習と復習カードで、間隔をあけて思い出す

6. 本サイトの使い方：読む・閉じる・思い出す

本サイトは、認知心理学で効果が確認されている「想起練習」と「間隔反復」に沿って作っています。要るのは「見れば分かる」ではなく「レビューの場で思い出せる」ことです。

読む前・読むとき・読んだ後

読む前到達点を見る

章の冒頭「この章で理解してほしいこと」「全体像」「読む前の問い」を見て、答えを予想してから読む。

読むとき自分のコードに当てる

危険な例を見たら「自分のリポジトリに似た書き方はないか」を考える。あれば場所をメモする。

読んだ直後閉じて言う

画面を閉じ、「この章は一言でいうと何の話か」「主な項目は何か」を自分の言葉で言う。言えなかった箇所だけ見直す。

翌日以降想起練習と学習記録

章末の想起練習を本文を見ずに行い、「学習記録」に記録する。1日後 → 3日後 → 7日後 → 14日後 → 30日後に復習日が表示される。

🔬根拠：テスト効果と分散学習

記憶から取り出す行為そのものが記憶を強くすること（テスト効果）、同じ時間なら日を分けて復習するほうが長く残ること（分散学習）は、多数の研究で確認されています。本サイトの想起練習・復習カード・学習記録はこの2つを実装したものです。
