第1章 セキュリティの全体像と用語

「脆弱性」「サイバー攻撃」のニュースを、自分のシステムに関係があるかどうか判断できるようになるための、最小限の地図です。守るものは3つ、言葉の関係は1枚の図、攻撃の入口は4つ、ニュースの用語は10個ほど。これだけで、この先の章と日々のニュースが読めるようになります。

🧭この章で理解してほしいこと
  • 守るものは3つ：機密性（漏れない）・完全性（書き換えられない）・可用性（止まらない）
    • 情報漏えい＝機密性が壊れた。改ざん・なりすまし送金＝完全性が壊れた。ランサムウェアで業務停止・DDoS＝可用性が壊れた
    • 事故はこの3つのどれか（または複数）が壊れること。対策もこの3つのどれを守るかで整理できる
  • 言葉の関係は1枚の図：脆弱性（穴）に脅威（狙う人・事象）が当たると攻撃が成立し、インシデント（事故）になる
    • リスク＝「起きやすさ × 被害の大きさ」。穴があっても、外から届かず被害も小さければリスクは低い
    • 対策は3種類：予防（穴をふさぐ）・検知（気づく）・回復（被害を小さく、元に戻す）
    • 「脆弱性がある」はすぐ事故ではない。「脆弱性がない」とも誰も言えない。だから予防・検知・回復をそろえる
  • 攻撃の入口は4つ：入力（コード）・部品（ライブラリ）・設定（公開範囲・権限）・人（フィッシング・パスワード）
    • 入力：利用者が送る文字列を命令として実行してしまう（第3章）、ログインや権限の穴（第4章）
    • 部品：使っているライブラリ・フレームワーク・OS の穴。ニュースの大半はこれ（第6章）
    • 設定：DB をインターネットに公開、ストレージを全員に公開、初期パスワードのまま（第7章）
    • 人：偽メールでパスワードを入力させる、同じパスワードの使い回し。開発者は多要素認証と最小権限で被害を広げない作りにする（第4章・第8章）
  • 認証と認可は別物：認証＝あなたは誰か（ログイン）、認可＝あなたは何をしてよいか（権限）
    • 「ログインしていれば OK」は認証だけ。他人の注文番号を URL に入れて見えてしまう事故は認可の不備
  • ニュースの読み方：CVE・CVSS・ゼロデイ・PoC・パッチ・EoL の6語で大半が読める
    • CVE：脆弱性に付く世界共通の番号（CVE-西暦-連番）
    • CVSS：深刻度の点数（0〜10）。7.0 以上は「重要」、9.0 以上は「緊急」で今日中に判断する
    • ゼロデイ：修正が出る前に悪用されている。PoC：攻撃できることを示すコードが公開されている（悪用が急増する合図）
    • パッチ：修正版。EoL：サポート終了＝今後パッチが出ない
    • 自分への影響は3問で判断：その部品を使っているか／外から届く経路があるか／直した版に上げたか
  • 今、何が多いか：IPA「情報セキュリティ10大脅威 2026」（組織）は 1位 ランサム攻撃、2位 サプライチェーンや委託先を狙った攻撃、3位 AI の利用をめぐるサイバーリスク、4位 システムの脆弱性を悪用した攻撃
    • 開発者に直結するのは 2位（部品・委託先）と 4位（自分のシステムの穴）
    • Web アプリの穴の分類は OWASP Top 10:2025。1位 アクセス制御の不備、2位 セキュリティ設定の不備、3位 ソフトウェアサプライチェーンの不備、5位 インジェクション

読み終えたら、本文を見ずに各項目を自分の言葉で説明できるか確かめてください。

1. 守るもの：機密性・完全性・可用性

セキュリティで守るものは、昔から3つに整理されています。機密性・完全性・可用性です。英語の頭文字をとって CIA と呼びます。事故のニュースは、必ずこの3つのどれかが壊れた話です。

守るもの一言でいうと壊れると（事故の形）主に関係する章
機密性漏れない個人情報の漏えい、ソースコードや API キーの流出、他人のデータが見える第3・4・5・7章
完全性書き換えられないWeb サイトの改ざん、注文金額の書き換え、なりすましによる送金、ライブラリへの不正コード混入第3・4・6章
可用性止まらないランサムウェアで業務停止、DDoS でサイトに繋がらない、バックアップがなく復旧できない第7・8章
💡イメージで理解する

自宅に置き換えると、機密性は「引き出しの中身を他人に見られない」、完全性は「留守中に勝手に模様替えされたり、書類を差し替えられたりしない」、可用性は「停電や鍵の紛失で家に入れない、ということがない」です。泥棒対策（機密性）だけがセキュリティではありません。

🔑覚え方：「漏れない・変わらない・止まらない」

事故のニュースを見たら、「どれが壊れたか」を一言で言ってみてください。情報漏えいは「漏れた」、改ざん・不正送金は「変わった」、ランサムウェア・DDoS は「止まった」。対策を考えるときも、この3つのどれを守る話かを先に決めると整理しやすくなります。

2. 言葉の関係：脆弱性・脅威・リスク・攻撃・インシデント・対策

ニュースや会議では、似た言葉がまとめて出てきます。関係を1枚の図にしておくと、どの言葉が出ても位置づけがわかります。

脆弱性に脅威が当たると攻撃が成立し、インシデントになる
脆弱性穴（欠陥・設定ミス）
＋
脅威狙う人・事象
→
攻撃穴を突く行為
→
インシデント事故（漏えい・改ざん・停止）
↑対策が止める
予防穴をふさぐ・狙われにくくする
検知起きたことに気づく
回復被害を小さく、元に戻す
リスク＝この流れが「起きやすいか」×「起きたら被害が大きいか」。穴があっても、外から届かず被害も小さければリスクは低く、逆に小さな穴でも個人情報の DB に直結していればリスクは高い。
言葉意味例
脆弱性
ぜいじゃくせい／vulnerability		攻撃に悪用されうる欠陥や設定ミス。「穴」SQL を文字列でつないでいる、DB がインターネットから見える、古いライブラリを使っている
脅威
threat		穴を突く可能性のある人や事象金銭目的の攻撃グループ、不満を持つ内部の人、自動で穴を探し回るボット
攻撃
attack		脅威が脆弱性を実際に突く行為SQL インジェクション、パスワードの総当たり、フィッシングメール
インシデント
incident		セキュリティ上の事故。機密性・完全性・可用性のどれかが壊れた（または壊れかけた）出来事個人情報の漏えい、サイト改ざん、ランサムウェアによる停止
リスク
risk		インシデントの「起きやすさ × 被害の大きさ」外から届く穴 × 個人情報 DB ＝ 高。社内だけ × 公開情報 ＝ 低
対策
countermeasure		予防・検知・回復のいずれかでリスクを下げる手段プレースホルダ（予防）、ログイン失敗のアラート（検知）、バックアップ（回復）
⚠️間違えやすい点
  • 「脆弱性がある」＝「すぐ事故」ではありません。脅威が届く経路と被害の大きさで緊急度が決まります（5節の3問）。
  • 逆に「脆弱性はない」とは誰にも言えません。だから予防だけでなく検知と回復をそろえるのが基本です（第8章）。
  • 「ウイルス対策ソフトを入れたから安全」は、入口4つのうち「人」の一部しか守っていません。

3. 攻撃はどこから入るか：4つの入口

攻撃の手口は無数にありますが、入口で分けると4つに整理できます。開発者が直接ふさげるのは最初の3つです。

4つの入口と、ふさぎ方を説明する章

自動で穴を探すボット

↓
① 入力第3・4章
② 部品第6章
③ 設定第7章
④ 人第4・8章で被害を限定
↓

入口何が起きるか典型例ふさぐ章

② 部品自分は何も書き換えていないのに、使っているライブラリ・フレームワーク・OS に穴が見つかるログ出力ライブラリの穴で任意コード実行、改ざんされたパッケージの取り込み第6章
③ 設定公開してはいけないものが公開されている。権限が広すぎる。初期設定のままDB がインターネットから接続できる、ストレージが全員に公開、管理画面が初期パスワード第7章
④ 人人をだましてパスワードを入力させる、同じパスワードの使い回しを突く、内部の人が持ち出すフィッシング、パスワードリスト攻撃、内部不正多要素認証（第4章）、最小権限とログ（第8章）で被害を限定
💡イメージで理解する

家にたとえると、① 入力は「窓や郵便受けから入れた物が家の中で勝手に動き出す」、② 部品は「建材そのものに欠陥が見つかる」、③ 設定は「鍵のかけ忘れ・合鍵の置きっぱなし」、④ 人は「訪問販売を装って鍵を開けさせる」です。大工（開発者）が直せるのは最初の3つで、4つ目は「開けてしまっても金庫は別に施錠されている」作りで被害を抑えます。

4. 認証・認可・セッション（さわりだけ）

第4章で詳しく扱いますが、この3語は会話に頻出するので先に区別しておきます。

認証にんしょう／Authentication、AuthN
あなたは誰かを確かめること。ログイン（ID とパスワード、多要素認証）がこれ。
認可にんか／Authorization、AuthZ
あなたは何をしてよいかを決めること。「この注文はあなたのものか」「管理者だけが削除できる」がこれ。認証が通っても、認可は別に確認が要る。
セッションSession
ログイン後、「さっき認証した人だ」と覚えておく仕組み。多くは Cookie に入れたセッション ID で実現する。これが盗まれると、パスワードなしでなりすまされる。
⚠️間違えやすい点

「ログインしている利用者だけがアクセスできる画面だから安全」は認証だけで止まっています。ログイン済みの利用者が URL の ID を書き換えて他人のデータを見る事故は、認可の不備です（OWASP Top 10:2025 の1位「アクセス制御の不備」）。

5. ニュースを読むための用語

脆弱性のニュースは、ほぼ決まった用語で書かれています。次の表の言葉がわかれば、記事の大半は読めます。

用語意味読み取ること
CVE
Common Vulnerabilities and Exposures		脆弱性1件ごとに付く世界共通の番号。CVE-西暦-連番 の形番号で検索すれば、影響範囲・修正版・回避策が公式情報として見つかる
CVSS
Common Vulnerability Scoring System		深刻度の点数（0.0〜10.0）。攻撃のしやすさ（ネットワーク越しか、認証が要るか）と影響の大きさで決まる7.0 以上は重要、9.0 以上は緊急。ただし自分への影響は別途判断（下の3問）
NVD／JVN脆弱性情報のデータベース。NVD は米国、JVN は日本（日本語）CVE 番号で引くと詳細がわかる
ゼロデイ
0-day		修正版が出る前に悪用されている（または公開された）脆弱性パッチがまだない。回避策（機能を止める・外から見えなくする）を探す
PoC
Proof of Concept		「この穴は本当に攻撃できる」と示すコードや手順PoC が公開されると、自動化された攻撃が数日で急増する。急ぐ合図
エクスプロイト
exploit		脆弱性を突く攻撃コードそのもの。「悪用」という意味でも使う「エクスプロイトが出回っている」＝実際に攻撃されている
パッチ／修正版脆弱性を直した更新。「x.y.z で修正」と書かれる自分の版が修正版より古ければ上げる
回避策
ワークアラウンド／mitigation		パッチを当てられないときに、影響を抑える設定変更機能を無効化する、該当の経路を外から遮断する、など
EoL
End of Life／サポート終了		開発元が更新をやめた状態。今後パッチは出ないEoL のものを使い続けること自体が脆弱性
RCE
Remote Code Execution／リモートコード実行		外から任意のプログラムを実行できてしまう、最も深刻な種類「認証不要で RCE」は最優先
権限昇格
privilege escalation		一般利用者が管理者の権限を得てしまう種類内部に入られた後の被害を大きくする
侵害／漏えい
breach		実際に入られた、持ち出された状態。脆弱性の「可能性」ではなく事故自分が利用者側なら、パスワード変更・多要素認証の確認
🎚️体験：CVSS の点数と区分

点数を動かすと、区分と一般的な対応の目安が変わります。区分は CVSS v3.x と v4.0 で共通です。

9.8
0 なし 0.1〜3.9 低 4.0〜6.9 中 7.0〜8.9 高 9.0〜 緊急
📰ニュースではこう報じられる：1本の記事を分解する

よくある記事の形：「〇〇（ライブラリ名）に深刻な脆弱性（CVE-20XX-NNNNN、CVSS 9.8）。認証なしでリモートコード実行が可能。修正版 x.y.z が公開。PoC が公開済みで、悪用も確認されている。」

  • 「〇〇に」→ 自分がその部品を使っているか（package-lock.json・requirements.txt・コンテナのイメージを確認）
  • 「認証なしでリモートコード実行」→ 最も深刻な種類。外から届くなら今日中
  • 「修正版 x.y.z」→ 自分の版と比べる。古ければ上げる
  • 「PoC 公開済み・悪用確認」→ 自動攻撃が来る前提で動く。上げられないなら回避策
🔑覚え方：自分への影響は3問で決める
  1. 使っているか：その部品（そのバージョン）が、自分のシステムに入っているか。
  2. 届くか：攻撃に使う経路（インターネットから到達する URL、ファイルアップロード、特定の機能）が、自分の構成で外から届くか。
  3. 直したか：修正版に上げたか。上げられないなら回避策を入れたか。

「使っている × 届く × 直していない」がそろったときだけ緊急です。どれか1つでも「いいえ」なら、優先度を下げて計画的に直します。

使っている？外から届く？対応の目安
はいはい今日中に修正版へ。上げられなければ回避策（経路の遮断・機能の無効化）を先に入れる
はいいいえ（社内のみ・該当機能を使っていない）次の定期リリースで上げる。内部に入られた後の被害を大きくするので放置はしない
いいえ—対応不要。ただし「使っていない」の確認は lock ファイルやイメージで裏を取る（間接的に使っていることが多い。第6章）

6. 今、何が多いか：IPA 10大脅威 2026 と OWASP Top 10:2025

「ニュースが多い」と感じるのは正しい感覚です。何が多いかは、日本では IPA（情報処理推進機構）が毎年1月に発表する「情報セキュリティ10大脅威」で、Web アプリの穴の分類は OWASP Top 10 で把握できます。

IPA「情報セキュリティ10大脅威 2026」（組織向け）

順位脅威開発者との関係
1位ランサム攻撃による被害侵入後に止められない構成、バックアップの不備（第7・8章）
2位サプライチェーンや委託先を狙った攻撃直結。使っている部品・委託先の穴（第6章）
3位AI の利用をめぐるサイバーリスク（初登場）AI 生成コードの穴、プロンプトインジェクション（第9章）
4位システムの脆弱性を悪用した攻撃直結。自分のシステムの穴と、パッチの遅れ（第3〜7章）
5位機密情報を狙った標的型攻撃最小権限とログ（第8章）
6位地政学的リスクに起因するサイバー攻撃（情報戦を含む）—
7位内部不正による情報漏えい等権限の棚卸し、操作ログ（第8章）
8位リモートワーク等の環境や仕組みを狙った攻撃VPN・リモート接続機器のパッチ（第7章）
9位DDoS 攻撃（分散型サービス妨害攻撃）WAF・CDN・レート制限（第7章）
10位ビジネスメール詐欺—（人・業務プロセスの課題）

番号分類一言でいうと本サイトの章

A02セキュリティ設定の不備公開範囲・初期設定・不要な機能の放置第7章

7. 役割分担：開発者は何を受け持つか

役割受け持つこと
開発者コードの穴を作らない、部品を最新に保つ、設定をコードで管理する、ログを設計する、事故の初動を知っている
インフラ・SREネットワークの公開範囲、OS・ミドルウェアのパッチ、バックアップ、監視基盤
セキュリティ担当・専門家脆弱性診断、脅威情報の分析、インシデント対応の指揮、規程の整備
クラウド事業者データセンター・物理機器・仮想化基盤の安全（責任共有モデル）。利用者のデータ・設定・権限は利用者の責任。詳しくは AWS 合格ノート 第2章
利用者パスワードの使い回しをしない、多要素認証を使う、不審なメールのリンクを開かない

小さなチームや個人開発では、これらを全部1人で受け持ちます。その場合も「開発者の範囲（コード・部品・設定・運用）」から順に固めるのが、費用対効果の高い順番です。

🛠️実務ではこうする
  • 脆弱性のニュースを見たら：CVE 番号で検索 → 「使っているか・届くか・直したか」の3問 → 今日中か次のリリースかを決めて、チームに一言で共有する（「〇〇 x.y 以下に RCE。うちは x.z で該当なし」）。
  • 会議で「脆弱性がある」と言われたら：「どの入口（入力・部品・設定・人）の話か」「壊れるのは漏れる・変わる・止まるのどれか」「CVSS と、外から届くか」を聞く。これで優先度が決まる。
  • 設計レビューで：「認証はあるが、認可はどこで確認するか」を必ず1回聞く。
📝用語の補足
ランサムウェア
データを暗号化して使えなくし、元に戻す代わりに金銭を要求する不正プログラム。近年は「公開するぞ」と二重に脅す。
DDoS 攻撃
多数のコンピューターから大量の通信を送りつけ、サービスを使えなくする攻撃（分散型サービス妨害攻撃）。
フィッシング
本物そっくりの偽メール・偽サイトで、パスワードやカード番号を入力させる手口。
サプライチェーン攻撃
自分を直接狙わず、使っている部品・委託先・配布経路を汚染して入り込む攻撃。
ボット
自動で動くプログラム。インターネット上の全アドレスに対して、既知の穴がないかを常時探し回っている。
IPA
情報処理推進機構。日本の公的機関で、脆弱性対策の資料や10大脅威を公開している。
OWASP
Web アプリケーションのセキュリティを扱う国際的な非営利団体。Top 10 や Cheat Sheet を公開している。

🧠 想起練習

本文を見ずに答えを思い出してから、各項目を開いて確認してください。

セキュリティで守るもの3つと、それぞれが壊れた事故の例を挙げてください。
機密性（漏れない）＝情報漏えい。完全性（書き換えられない）＝改ざん・不正送金。可用性（止まらない）＝ランサムウェアによる停止・DDoS。
脆弱性・脅威・攻撃・インシデント・リスクの関係を1文で説明してください。
脆弱性（穴）に脅威（狙う人・事象）が当たると攻撃が成立しインシデント（事故）になる。リスクはその起きやすさ×被害の大きさ。
対策の3種類は何ですか。それぞれ例を1つ。
予防（穴をふさぐ：プレースホルダ）、検知（気づく：ログイン失敗のアラート）、回復（元に戻す：バックアップ）。
攻撃の4つの入口と、開発者が直接ふさげるのはどれですか。
入力・部品・設定・人。開発者が直接ふさげるのは入力・部品・設定。人は多要素認証と最小権限で被害を限定する。
認証と認可の違いを、事故の例を使って説明してください。
認証＝あなたは誰か（ログイン）。認可＝何をしてよいか。ログイン済みの利用者が URL の ID を変えて他人の注文を見られるのは、認証は通っているが認可が抜けている事故。
CVE と CVSS は何ですか。CVSS で「重要」「緊急」の境目は？
CVE＝脆弱性の世界共通の番号。CVSS＝深刻度の点数（0〜10）。7.0 以上が高（重要）、9.0 以上が緊急。
ゼロデイ・PoC・EoL をそれぞれ一言で。
ゼロデイ＝修正が出る前に悪用されている。PoC＝攻撃できることを示すコード（公開されると攻撃が急増）。EoL＝サポート終了で今後パッチが出ない。
脆弱性のニュースを見たとき、自分への影響を判断する3問は？
その部品を使っているか／攻撃経路が外から届くか／修正版に上げた（回避策を入れた）か。3つそろったときだけ緊急。
IPA 10大脅威 2026（組織）の上位4つと、開発者に直結する2つは？
1位 ランサム攻撃、2位 サプライチェーン・委託先、3位 AI の利用、4位 システムの脆弱性の悪用。直結は2位と4位。
OWASP Top 10:2025 の1位と、新しく入った分類を挙げてください。
1位はアクセス制御の不備。新顔は A03 ソフトウェアサプライチェーンの不備と A10 例外的な状況への不適切な対応。
